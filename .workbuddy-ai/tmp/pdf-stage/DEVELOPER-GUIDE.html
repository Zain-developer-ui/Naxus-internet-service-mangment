1. Overview

NEXUS is a server-rendered MVC application that manages the life cycle of an internet service subscriber: order, feasibility survey, installation, activation, monthly billing and payment, with supporting back-office modules for inventory, procurement, staff and site configuration.

The design brief was "portfolio-grade, not a student project." That shaped several decisions:

  • No Bootstrap. The layout, components and design tokens are hand-written CSS.
  • No emojis, no filler comments, no boilerplate docblocks. Comments explain

why, briefly, and only where the reason is not obvious from the code.

  • No fabricated statistics, testimonials or placeholder numbers anywhere in the

UI. Every figure on every screen is read from the database.

The system is one ASP.NET Core project. There is no separate class library, no separate API layer, and no SPA framework — views are Razor, behaviour is progressive-enhancement JavaScript, and the server owns all the state.

3.1 The layering rule

Controller  →  Service  →  DbContext  →  SQL Server
     ↑             ↓
  ViewModel     Result<T>
  • Controllers are thin. They bind input, call one service method, map the

Result<T> to a response, and return a view. Business rules do not live in controllers.

  • Services own the rules. Everything decision-shaped — can this connection

be billed, how much of the advance applies, is this CNIC already taken — is in a service.

  • BillCalculator is pure. No DbContext, no ILogger, no async. The

arithmetic can be reasoned about and tested on its own.

4. Getting the Project Running

4.1 Prerequisites

Requirement Version
.NET SDK 8.0 or later
SQL Server 2019 or later (Express is fine)
Node.js Not required — there is no front-end build

4.2 First run

1. Restore and build.

dotnet restore
dotnet build

2. Point the connection string at your SQL Server.

Edit appsettings.json:

"ConnectionStrings": {
  "NexusDb": "Server=<your-server>;Database=NexusDb;User Id=<user>;Password=<password>;TrustServerCertificate=True;MultipleActiveResultSets=True;Connect Timeout=60"
}

3. Apply the database migrations.

dotnet ef database update

This creates the schema from the migration history. The __EFMigrationsHistory table records which migrations have been applied.

If dotnet ef is not installed:

dotnet tool install --global dotnet-ef

4. Run.

dotnet run

The application listens on http://localhost:5096 (and HTTPS on the adjacent port). Reference data — cities, plans, prices, discount tiers, equipment and the seed administrator — is inserted on startup. Every seeding block checks before inserting, so restarting the application is harmless.

5.2 Why the currency symbol is pinned

Views format money with ToString("C"), which takes the symbol from the host culture. The same figure would then render as $ on one machine and Rs on another, making invoice screenshots inconsistent. Program.cs reads NexusFinance:CurrencySymbol and sets it on the default culture at startup.

5.3 Runtime settings (database-backed)

Settings that the administrator can change are stored in the SiteSettings table and read through ISiteSettingsService. These are not in appsettings.json because they must be editable from the running application:

Key Effect
site.name, site.company, site.email, site.phone, site.address Public site identity
brand.logo Header logo
feature.registration Public self-service ordering
feature.feedback Customer feedback form
feature.autoInvoice Automatic invoice generation
security.sessionMinutes Session lifetime

SiteSettingsService caches values and invalidates on write, so a settings change is visible on the next request without a restart.

6. Architecture

6.1 The Result pattern

No service method throws for an expected failure. Everything returns Result<T>:

public sealed class Result<T>
{
    public bool IsSuccess { get; }
    public T? Value { get; }
    public ErrorKind Kind { get; }              // None, NotFound, Validation,
                                                // Conflict, Unauthorized,
                                                // Forbidden, Failure
    public string? Message { get; }
    public IReadOnlyDictionary<string, string[]>? Errors { get; }
}

Constructors are private; use the factories:

Result<T>.Ok(value)
Result<T>.Fail(ErrorKind.Validation, "message")
Result<T>.Fail("FieldName", "message")          // field-scoped validation
Result<T>.NotFound("Connection")
Result<T>.Conflict("already billed for this period")
Result<T>.Forbidden("this resource")

Controllers translate Kind into a response:

Kind Controller response
None (success) Render the view, or redirect
NotFound 404
Validation Re-render with the message in TempData["Error"]
Conflict Re-render with the conflict message
Forbidden 403
Unauthorized Redirect to sign-in

Why: a Result<T> chain makes every failure path visible in the signature. An exception-based design hides them, and the controller ends up guessing which exceptions to catch.

6.2 Dependency injection

Everything is registered in Program.cs with an explicit interface:

builder.Services.AddScoped<IBillingService, BillingService>();
builder.Services.AddScoped<IPlanChangeService, PlanChangeService>();

Services are Scoped (one per request) because they hold a DbContext. IPasswordService is a Singleton — it is stateless and hashing is CPU-bound.

6.3 Middleware order

Order matters, and Program.cs is deliberately explicit:

nonce middleware        →  a nonce per request, before anything renders
exception handler       →  production only
status code pages       →  branded 404 / 403 / 500 pages
UseHttpsRedirection
UseNexusSecurityHeaders →  CSP and the other response headers
UseStaticFiles
UseRouting
UseRateLimiter
UseAuthentication
UseAuthorization
MapControllerRoute

UseRateLimiter sits before authentication because throttling must apply to unauthenticated traffic — the sign-in endpoint being the whole point.

7. Domain Model

7.1 Core entities

Customer ─────┬─── ConnectionOrder ───┬─── Connection ───┬─── Bill ─── BillLine
              │                      │                  ├─── Payment
              │                      └─── FeasibilityCheck
              │                                         └─── ConnectionCharge
              ├─── AppUser (login)
              └─── Feedback

Plan ─── PlanPrice (per billing cycle)   City ─── RetailShop ─── Employee

7.2 Selected entities

Customer — the subscriber. Holds the account ID, CNIC, contact details, address, city, an optional organisation name for corporate accounts, and the outlet it was sold from. LiveConnectionCount drives the bulk-discount tier.

AppUser — the login record. References a Customer for customer accounts, or an Employee for staff. Role is a string matching NexusRoles.

ConnectionOrder — the order, before a physical line exists. Carries the plan, connection type, billing cycle, installation address, the quoted amount, and the advance accounting fields:

public decimal QuotedAmount { get; set; }
public decimal AdvanceApplied { get; set; }
public decimal AdvanceRemaining => Math.Max(0m, QuotedAmount - AdvanceApplied);
public DateTime? AdvanceAdjustedOn { get; set; }

AdvanceApplied is the money already credited against bills. AdvanceRemaining is computed — it is never stored, so it cannot drift.

Connection — the physical line, with a number like CON-B-000004 and a status. CanBeBilled() is true only for Active.

Bill — one invoice for one period. Status walks Draft → Issued → PartiallyPaid → Paid, or Overdue after the due date, or Cancelled. The stored amounts are SubTotal, DiscountAmount, TaxableAmount, ServiceTaxAmount, TotalAmount and AmountPaid.

PlanChangeRequest — a customer's request to move plan, waiting for admin approval. One open request per connection.

7.3 Enums are stored as strings

Every enum is persisted as its name, not its ordinal:

b.Property(o => o.Status).HasConversion<string>().HasMaxLength(30);

Why: a database someone can read. Status = 'Active' is self-describing; Status = 1 is not, and it breaks the moment someone reorders the enum members.

Consequence: raw SQL seeds and manual fixes must use the string name.

UPDATE Bills SET Status = 'Issued' WHERE Id = 6;   -- correct
UPDATE Bills SET Status = 1        WHERE Id = 6;   -- EF will never match this

8.4 Query patterns

Include only what the screen needs.

var bill = await _db.Bills
    .AsNoTracking()
    .Include(b => b.Customer).ThenInclude(c => c.City)
    .Include(b => b.Connection)
    .Include(b => b.Lines)
    .FirstOrDefaultAsync(b => b.Id == billId, ct);

Always pass a CancellationToken so an abandoned request stops the query.

Date ranges must cover the whole end day.

q.Where(b => b.IssuedOn < to.Date.AddDays(1))   // correct
q.Where(b => b.IssuedOn <= to)                  // loses the last day's rows

Do not call a computed property inside a LINQ-to-Entities predicate. EF cannot translate it and the query fails at runtime. NotificationService once used IsPending, a computed property, which crashed the admin dashboard. It now filters on the stored column:

c.BilledOnBillId == null       // translatable
c.IsPending                    // not translatable — runtime failure

9. The Billing Engine

This is the most intricate part of the system and deserves its own section.

9.1 Two entry points, one code path

Method Purpose
PrepareDraftAsync(customerId, connectionId, start, end) Preview — builds the lines, writes nothing
GenerateForPeriodAsync(start, end) The monthly run — builds and saves a bill per active connection

Both call BuildLinesAsync and BillCalculator, so a preview can never disagree with what the run produces.

9.2 Building the lines

BuildLinesAsync adds, in order:

  1. Rental — BillCalculator.RentalLine, priced at the plan's rate for the

cycle, multiplied by the number of months in the period.

  1. Usage / calls — metered usage above the plan's allowance, and local / STD

/ mobile call minutes from CallUsages.

  1. Advance — ApplyAdvanceAsync, a credit (see 9.3).
  2. One-off charges — pending ConnectionCharges for the connection.

9.3 The advance rule

var charges = Math.Max(0m, lines.Sum(l => l.LineAmount));
var applied = Math.Min(order.AdvanceRemaining, charges);

The advance is credited only as far as the period's own charges allow. Three guards enforce it:

Guard 1 — never more than the remaining balance.

if (order is null || order.AdvanceRemaining <= 0m) return null;

Guard 2 — never applied twice.

if (order.AdvanceApplied > 0m) return null;

Guard 3 — no connection may carry two advance lines.

private Task<bool> HasAdvanceLineAsync(int connectionId, CancellationToken ct) =>
    _db.Bills.AnyAsync(b => b.ConnectionId == connectionId &&
                            b.Status != BillStatus.Cancelled &&
                            b.Lines.Any(l => l.ChargeType == ChargeTypes.AdvancePayment), ct);

Why guard 2 and 3 both exist. ApplyAdvanceAsync runs during preview as well as during the run. Preview writes nothing, so AdvanceApplied is not decremented there — and because the guard could only see the column, a later period would credit the same money again. The connection this was found on had its advance applied three times across three bills. HasAdvanceLineAsync checks what actually reached the database, which is the durable record; AdvanceApplied catches the order that was drawn down under the older code.

MarkAdvanceAdjusted consumes the applied part only when the bill is saved, inside the same transaction. A preview therefore never spends the advance.

9.4 The arithmetic

BillCalculator is a pure static class over ChargeLine records:

subtotal  = sum of all lines
discount  = sum of DISCOUNTABLE lines × tier rate
taxable   = subtotal − discount
tax       = max(0, taxable) × 12.24%
total     = max(0, taxable + tax)

Two of those lines encode a business rule that is easy to get wrong:

The discount base is not the subtotal. Per the requirements, the bulk rate applies to the advance and the security deposit — the one-off money a customer puts down — and to installation. It does not apply to the recurring rental. Discounting the rental would quietly under-bill every month.

private static readonly HashSet<string> Discountable =
    new(StringComparer.OrdinalIgnoreCase)
    {
        AdvancePayment, SecurityDeposit, Installation
    };

A bill is never negative.

public decimal ServiceTaxAmount => TaxConstants.Compute(Math.Max(0m, TaxableAmount));
public decimal TotalAmount => Math.Max(0m, TaxableAmount + ServiceTaxAmount);

Without the clamps, a credit line larger than the charges produces a negative tax — a refund of tax the customer never paid, which is not a thing. A fresh charge added after the advance was computed can still push the total below zero, so the clamp exists for more than just consistency.

9.5 Transactions and the retry strategy

EF's EnableRetryOnFailure is configured, and a retry strategy cannot replay a transaction it did not open. A hand-rolled transaction therefore has to be wrapped:

var strategy = _db.Database.CreateExecutionStrategy();

await strategy.ExecuteAsync(async () =>
{
    await using var tx = await _db.Database.BeginTransactionAsync(ct);

    // ... work ...

    await tx.CommitAsync(ct);
});

Opening a transaction outside the strategy throws at runtime.

9.6 Bill numbering

IAccountIdGenerator.NextBillNumberAsync(period, ct) produces INV-<year>-<5-digit serial>, scoped per year. It reads the highest existing number for the period inside the same transaction, so concurrent runs cannot collide.

Receipt numbers follow the same idea: RCP-<yyyymm>-<5-digit serial>.

10. Authentication and Authorisation

10.1 Sign-in

Cookie authentication with a custom scheme name (SignInService.Scheme).

POST /Account/Login
  → ISignInService.ValidateAsync(accountIdOrEmail, password)
  → IPasswordService.Verify(hash, password)
  → claims principal built from the user row
  → cookie issued

The identity cookie carries:

Claim Helper
NameIdentifier User.UserId()
Name User.AccountId()
Role User.IsInRole(...)
customer_id User.CustomerId() — int?
shop_id User.ShopId() — int?
employee_id User.EmployeeId() — int?

All of these are extension methods on ClaimsPrincipal in Common/Extensions/ClaimsPrincipalExtensions.cs.

10.2 Passwords

Hashing uses ASP.NET Core Identity's PasswordHasher<T> — PBKDF2 with HMAC-SHA256, 100,000+ iterations, per-user salt. Nothing in this project stores or logs a plaintext password.

Additional controls:

  • Lockout after repeated failed attempts.
  • Rate limiting per IP on the sign-in endpoint, 10 attempts per minute by

default, returning HTTP 429. The limit is configurable so automated end-to-end tests, which drive many sessions from one address, do not trip it on their own traffic.

  • Cookie hardening: HttpOnly, SameSite=Lax, SecurePolicy=SameAsRequest.
  • No sliding expiration — an idle session expires rather than renewing itself.

10.3 Authorisation

Role checks use [Authorize(Roles = ...)] with the NexusRoles constants:

[Authorize(Roles = NexusRoles.Accounts + "," + NexusRoles.Admin)]
Controller Roles
AdminController and the admin-only controllers Admin
OperationsController Technical, Accounts, Admin
AccountsController Accounts, Admin
BillsController Customer, Accounts, Admin, Retail
RetailController Retail, Admin
SearchController All staff
CustomerController Customer, plus staff with an explicit ?id=
OrdersController.New Public, gated by feature.registration
FeedbackController Customer, Admin, gated by feature.feedback

Per-action overrides tighten the class-level rule where needed:

[Authorize(Roles = NexusRoles.Accounts + "," + NexusRoles.Admin)]
[HttpPost]
[ValidateAntiForgeryToken]
public async Task<IActionResult> Issue(int id, CancellationToken ct)

10.4 Ownership, not just role

A role check answers "may this kind of user call this action?" It does not answer "may this user touch this row?" — that is a separate check, and skipping it is how IDOR bugs happen.

BillsController.Details:

if (User.IsInRole(NexusRoles.Customer))
{
    var own = User.CustomerId();
    var owner = await _billing.ForCustomerAsync(own ?? 0, ct);
    var belongs = owner.IsSuccess && owner.Value!.Any(b => b.Id == id);
    if (!belongs) return Forbid();
}

A customer can only open a bill they own. CustomerController does the same through ResolveCustomerId, which reads the id from the claim for a customer and accepts ?id= only from staff.

11. Security

11.1 Response headers

SecurityHeadersMiddleware sets, on every response:

Header Value
X-Content-Type-Options nosniff
X-Frame-Options DENY
Referrer-Policy strict-origin-when-cross-origin
Permissions-Policy camera=(), microphone=(), geolocation=(), payment=()
Cross-Origin-Opener-Policy same-origin
Strict-Transport-Security max-age=31536000; includeSubDomains (HTTPS only)
Content-Security-Policy see below

11.2 Content Security Policy

default-src 'self';
script-src 'self' 'nonce-<per-request-nonce>';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
font-src 'self' data:;
connect-src 'self';
form-action 'self';
frame-ancestors 'none';
base-uri 'self';
object-src 'none'

Notice script-src has no 'unsafe-inline'. Inline scripts are permitted only with a nonce, generated per request and exposed to the views.

Two pieces make this work:

  1. Middleware generates the nonce and stores it in HttpContext.Items["csp-nonce"].
  2. ScriptNonceTagHelper reads it and attaches it to inline <script> tags.
[HtmlTargetElement("script")]
public class ScriptNonceTagHelper : TagHelper

Only inline scripts get the nonce. A <script src="..."> tag must not carry one — the browser ignores the attribute on externally loaded scripts, and adding it by accident hides a real inline script from the policy.

style-src still allows 'unsafe-inline'. That is a known, deliberate gap: a handful of older views use inline style attributes. script-src is the important half, and it is locked down.

11.3 Cross-site request forgery

Every state-changing action is a POST with [ValidateAntiForgeryToken], and every form emits @Html.AntiForgeryToken().

Two consequences worth knowing:

  • Logout is POST, not a link. A GET logout is CSRF-able and causes redirect

loops when combined with cookie expiry.

  • **[ValidateAntiForgeryToken] plus an IFormCollection parameter returns

400.** Read Request.Form directly instead when you need raw form access.

11.4 Input handling

  • Data annotations on every view model.
  • SuppressImplicitRequiredAttributeForNonNullableReferenceTypes = true, so a

nullable-reference-type annotation does not silently make an optional field required. Requiredness comes from [Required] only.

  • Optional text fields are tested with string.IsNullOrWhiteSpace, not is null

— a browser submits an empty string, not a null.

  • Client-side validation mirrors the server rules and is **driven by the

server's data-val-* attributes**, so the two cannot drift.

See section 16.

12. Front-End

12.1 No framework

The CSS is hand-written with custom properties for the design tokens. There is no Bootstrap, no Tailwind, no compiled stylesheet step.

wwwroot/css/
  base.css          reset and tokens
  layout.css        page shell, navbar, footer
  sidebar.css       dashboard sidebar
  components.css    cards, badges, buttons, forms
  tables.css        data tables
  billing.css       invoice layout
  dashboards-luxury.css   dashboard-specific treatments
  auth.css          sign-in screens
  ...

Design principles, in the order they constrain decisions:

  • Restrained. No gradients used as decoration, no glassmorphism, no neon.
  • Real numbers only. A screen with no data shows an empty state that explains

what would make records appear — never a plausible-looking placeholder.

  • Typography and spacing do the work that colour would otherwise be asked to do.
  • No search bar in the navbar.

12.2 Layouts

There are exactly two layouts:

Layout Used by
_Layout Public pages
_DashboardLayout Every signed-in panel

_DashboardLayout renders _Sidebar on the left and the content beside it, and exposes two sections:

@section DashboardStyles { ... }
@section DashboardScripts { ... }

The section names are DashboardStyles and DashboardScripts. Writing @section Scripts in a dashboard view throws a 500 at render time. Public views use Scripts.

12.3 Sidebar

_Sidebar.cshtml picks its menu from the signed-in identity:

var role = User.SidebarRole().ToLowerInvariant();

It does not read ViewData["UserRole"]. The identity is the only source, so a page cannot accidentally render another role's menu.

Active-item highlighting: the page sets ViewData.SetActiveItem("bills"), which the partial matches against. A page may claim more than one key, which is how the overdue filter lights both its own entry and the bills entry.

12.4 JavaScript

Plain ES modules and IIFEs, no bundler. Each file has one job:

File Responsibility
site.js Shared behaviour: decorative icon pass, reveals, dropdowns
navigation.js Sidebar toggle and aria-current marking
validation.js Client validation driven by server data-val-* attributes
dashboard.js Dashboard charts and counters
forms.js Form helpers, conditional fields
search.js Search and filter behaviour
settings.js Settings screen
plan-edit.js Plan editor, tariff field visibility
charts.js Chart.js wiring
modal.js Dialogs
tier-edit.js Bulk discount tier editor
new-connection.js, purchase-order.js Multi-step / repeatable-row forms

Two patterns worth knowing:

  • Validation is attribute-driven. validation.js reads data-val-* off the

input rather than holding its own regexes. A regex rule uses data-val-regex-pattern and data-val-regex; a length rule uses data-val-length-min and data-val-length. Adding a hard-coded client rule reintroduces exactly the drift this design removed.

  • Two accessibility passes are centralised. Decorative Font Awesome icons get

aria-hidden in site.js (initDecorativeIcons), and aria-current="page" is applied to the active sidebar entry in navigation.js (initAriaCurrent). Neither is written by hand in markup.

14. Conventions

14.1 Code style

The code must read as though a person wrote it.

  • No emojis, anywhere, in any file.
  • No filler comments. No comment that restates the line below it.
  • No boilerplate docblocks. No /// <summary> on every member "for

completeness".

  • **Comments explain why.** If the reason for a piece of code is not obvious

from the code, a short comment earns its place. If it is obvious, a comment is noise.

/**
 * The advance taken at connection time, credited against the bill. It is only
 * ever absorbed as far as the period's own charges allow: a bill that came out
 * negative would read as a refund the customer never asked for, and the surplus
 * would be stranded.
 */

That is the register. An explanation of a real decision, and nothing else.

14.2 Async

  • All I/O is async.
  • Every async service and controller method takes a CancellationToken and

passes it down.

  • No .Result or .Wait() — both deadlock under a synchronisation context.

Razor view Views/<Controller>/<Action>.cshtml
Migration Descriptive_Name in PascalCase

14.4 Nullability

Nullable reference types are enabled. Result<T>.Value is nullable by design — an unsuccessful result has no value — and the compiler is right to warn. Do not suppress with !; handle it:

result.Value ?? Array.Empty<BillSummary>()

15. Development Gotchas

These have all cost time at least once. They are recorded here so they cost it only once.

EF Core and C#

Date ranges must cover the whole end day.

x < to.Date.AddDays(1)     // correct
x <= to                    // silently drops the final day

Computed properties are not translatable. A get-only property cannot appear inside a LINQ-to-Entities predicate. Filter on the stored column instead.

Enums are stored as strings. Raw SQL must use the name: 'Active', not 1.

Byte arrays and HasMaxLength. MaxLength on nvarchar counts characters; char and varchar count bytes. IdFormats and the configurations already account for the difference.

Fail needs an ErrorKind for a general message. The single-argument overload takes a field name:

Result<T>.Fail("Amount", "Enter an amount")                  // field-scoped
Result<T>.Fail(ErrorKind.Validation, "Something went wrong") // general

A GET and a POST action cannot share a name. Attributes are not part of the method signature, so C# raises CS0111. Give the POST a different method name and alias it:

[HttpPost]
[ActionName("Confirm")]
public async Task<IActionResult> ConfirmPost(...) { }

User.EmployeeId() returns int?. A service taking an int raises CS1503. Match the nullable type.

Razor

Dashboard section names are DashboardStyles and DashboardScripts. @section Scripts in a dashboard view is a 500.

Static members are not reachable through an instance in Razor (CS0176). Write the full type name.

decimal / decimal is not implicitly a double. Cast explicitly:

(double)(amount / total)

A new _ViewImports.cshtml must re-register the tag helpers. The project's has:

@addTagHelper *, NEXUS.Services

Without it, ScriptNonceTagHelper never runs and every inline script is blocked by the CSP.

CSS and JavaScript

Scope a DOM query to the right root. Not every input lives inside the form. The order summary on /Orders/New is an <aside> beside the form, so a form-scoped query does not find it — query from document.

Every input must be inside its form, or carry form="<id>". An input outside the form element is simply not submitted, and the failure is silent.

Do not add inputmode="numeric" to dash-required fields. A mobile numeric keypad has no dash key, so the phone field becomes impossible to fill.

Align the client rule with the server rule, or do not add one. The phone validation once disagreed between client and server — ^03\d{9}$ against ^0\d{3}-\d{7}$ — which silently blocked the entire order wizard.

document.querySelector runs before the DOM is ready unless the script is deferred or wrapped. All scripts here are deferred or placed at the end.

Database

EnableRetryOnFailure and a manual transaction do not mix. Wrap in CreateExecutionStrategy().ExecuteAsync(...) (section 9.5).

A unique index on Connections.OrderId means one order produces one connection. Do not try to create a second.

EnableRetryOnFailure masks nothing — a genuine constraint violation still surfaces, after the retries.

Process

A running application locks its executable. dotnet build fails with MSB3021/MSB3027 while the app is running. Stop the app first. The compile itself is usually clean — check whether the errors are all copy errors before hunting a code fault.

Razor runtime compilation is off (section 4.3).

style-src 'unsafe-inline' A few older views use inline style attributes Lower than a script gap, but real

Single-currency The symbol is configurable, but there is no rate table or multi-currency support Fine for one market only
