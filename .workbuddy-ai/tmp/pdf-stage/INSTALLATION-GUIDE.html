1. What You Need

1.1 Minimum requirements

Component Minimum Recommended
Operating system Windows 10 / Windows Server 2016 Windows 11 / Server 2019+
Processor 2 cores 4 cores
Memory 4 GB 8 GB
Disk 2 GB free 10 GB free
.NET SDK 8.0 8.0 (latest patch)
SQL Server 2019 Express 2019+ Standard/Developer

SQL Server Express is sufficient. The schema, the data and the query load all sit comfortably inside the Express limits, and the system is verified against Express.

1.2 What the application uses

  • .NET 8.0 — the runtime
  • SQL Server — database
  • Port 5096 (HTTP) and the paired HTTPS port — web
  • No external service, no cloud account, no internet connection at runtime

Font Awesome and Chart.js are self-hosted in wwwroot/lib/. The application makes no outbound network calls during normal operation.

2.1 .NET 8 SDK

Download from .

If you only need to run a published build rather than build from source, the ASP.NET Core 8 Runtime is enough — but for a development or evaluation machine, install the full SDK.

Either edition works:

  • SQL Server Developer — free for non-production use, full feature set.

3. Getting the Source

Copy or clone the project folder to a location of your choosing:

C:\Projects\Naxus-internet-service-mangment\

Confirm the folder contains NEXUS.Services.csproj and NEXUS.Services.sln at its root:

cd /d C:\Projects\Naxus-internet-service-mangment
dir *.csproj

4. Database Setup

You have two routes. Route A (migrations) is recommended — it is the one that stays correct as the schema evolves.

4.1 Route A — Apply the migrations (recommended)

The migrations in Data/Migrations/ build the entire schema from nothing.

Step 1 — Make sure the connection string points at your SQL Server. See section 5.

Step 2 — Apply.

cd /d C:\Projects\Naxus-internet-service-mangment
dotnet ef database update

This creates the NexusDb database if it does not exist, then applies every migration in order. The __EFMigrationsHistory table records what was applied.

Step 3 — Verify.

In SSMS, connect to your instance and confirm NexusDb exists with tables including Customers, ConnectionOrders, Connections, Bills, BillLines, Payments, Plans, Users.

Step 4 — Reference data seeds itself. The first time the application runs, the seeder inserts cities, plans, prices, discount tiers, equipment and the administrator account. See section 7.

4.2 Route B — Restore a database backup

If you were given a .bak file alongside the source:

RESTORE DATABASE NexusDb
FROM DISK = 'C:\Path\To\NexusDb_Full.bak'
WITH MOVE 'NexusDb'     TO 'C:\Program Files\Microsoft SQL Server\MSSQL16.SQLEXPRESS\MSSQL\DATA\NexusDb.mdf',
     MOVE 'NexusDb_log' TO 'C:\Program Files\Microsoft SQL Server\MSSQL16.SQLEXPRESS\MSSQL\DATA\NexusDb_log.ldf',
     REPLACE;

Adjust the MOVE paths to your own instance's data directory. Using the wrong path is the most common cause of a failed restore.

A .bak carries a specific SQL Server edition and version. If your server refuses it, use Route A instead — the migrations always produce a schema your own server can run.

4.3 Granting the application database access

If you are connecting with a SQL login, confirm it can reach the database:

USE NexusDb;
GO
CREATE USER [nexus_app] FOR LOGIN [nexus_app];
ALTER ROLE db_datareader ADD MEMBER [nexus_app];
ALTER ROLE db_datawriter ADD MEMBER [nexus_app];
GO

For the evaluation setup the connection uses the sa account, which already has everything it needs. Do not ship sa credentials. Create a dedicated, least-privilege login before any real deployment (section 8.3).

5. Configuration

All configuration lives in appsettings.json at the project root.

5.1 Connection string

"ConnectionStrings": {
  "NexusDb": "Server=<SERVER>;Database=NexusDb;User Id=<USER>;Password=<PASSWORD>;TrustServerCertificate=True;MultipleActiveResultSets=True;Connect Timeout=60;Min Pool Size=5"
}
Part Notes
Server .\SQLEXPRESS for a local default instance, or <machine>\SQLEXPRESS
Database NexusDb — created by the migrations if absent
User Id / Password SQL login credentials
TrustServerCertificate=True Required with a self-signed development certificate
MultipleActiveResultSets=True Used by some query paths
Connect Timeout=60 Seconds; raised for slower machines
Min Pool Size=5 Keeps a warm connection pool

For Windows authentication instead of a SQL login:

Server=.\SQLEXPRESS;Database=NexusDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True;

5.2 Currency

"NexusFinance": {
  "CurrencyCode": "USD",
  "CurrencySymbol": "$"
}

The symbol is applied to the default culture at startup. Change it here to re-brand the whole application's money display in one place.

Do not rely on the host machine's regional settings for the symbol. Views format with ToString("C"), which reads the symbol from the culture — that is exactly why the symbol is pinned here.

5.3 Security limits

"Security": {
  "LoginRateLimit": {
    "PermitLimit": 10,
    "WindowMinutes": 1
  }
}

Sign-in attempts per IP address per window. Ten per minute is far above a human typing rate and well below what a script needs to be effective.

If you run automated end-to-end tests, raise these. A test harness drives many browser sessions from one address and will otherwise trip the limiter on its own traffic. Keep the defaults in production.

5.4 Logging

"Serilog": {
  "MinimumLevel": {
    "Default": "Information",
    "Override": {
      "Microsoft.AspNetCore": "Warning",
      "Microsoft.EntityFrameworkCore.Database.Command": "Warning"
    }
  }
}

Logs are written to the console and to Logs/nexus-<date>.log, rolling daily, with fourteen days retained. To capture SQL statements, change the EF Core override to Information — useful for diagnosis, noisy for production.

6. Building and Running

6.1 Restore and build

cd /d C:\Projects\Naxus-internet-service-mangment
dotnet restore
dotnet build

A clean build reports 0 errors. Warnings, if any, are listed with their file and line.

6.2 Run

dotnet run

The console shows:

[HH:mm:ss INF] NEXUS starting up
[HH:mm:ss INF] Reference data seeded
Now listening on: http://localhost:5096

Open in a browser.

To stop, press Ctrl+C.

6.3 Running from Visual Studio

  1. Open NEXUS.Services.sln.
  2. Set NEXUS.Services as the startup project.
  3. Press F5, or Ctrl+F5 to run without the debugger.

The first build restores NuGet packages automatically and takes a few minutes. Subsequent builds take seconds.

6.4 Changing the port

Edit Properties/launchSettings.json:

"applicationUrl": "http://localhost:5096;https://localhost:7096"

6.5 A note on locked files

If the application is running, dotnet build fails with:

error MSB3021: Unable to copy file "...\NEXUS.Services.exe"
error MSB3027: The file is locked by: "NEXUS.Services (1234)"

The running process holds its own executable. Stop the application, then build. The MSB errors are copy errors, not compile errors — the code itself is usually fine.

7. First-Run Checklist

Work through this after the application starts for the first time.

7.1 Confirm the seed data

Check Expected
Home page loads Plans are listed, navbar shows the site name
/Plans Dial-Up, Broadband and Telephone plans with prices
Sign-in with A0000000000001 / Nexus@2027 Admin dashboard loads
/Admin/Settings/Cities Cities present, each with a code
/Admin/Settings/Discounts Bulk discount tiers present
/Admin/Inventory Equipment catalogue populated
Notification bell Live counts, or empty states that explain themselves

7.2 Verify the database

Run in SSMS against NexusDb:

SELECT COUNT(*) AS Users        FROM Users;
SELECT COUNT(*) AS Plans        FROM Plans;
SELECT COUNT(*) AS Cities       FROM Cities;
SELECT COUNT(*) AS Settings     FROM SiteSettings;
SELECT COUNT(*) AS Migrations   FROM __EFMigrationsHistory;

Users should be at least 1 (the administrator), Plans at least 10, Cities several, and Migrations should equal the number of migration files in Data/Migrations/ (the .Designer.cs files do not count).

7.3 Sign in to all four staff panels

Role Account ID Password Should land on
Admin A0000000000001 Nexus@2027 /Admin/Dashboard
Retail R0000000000001 Nexus@2026 /Retail/Dashboard
Technical T0000000000001 Nexus@2026 /Technical/Dashboard
Accounts F0000000000001 Nexus@2026 /Accounts/Dashboard

If any account is missing, check that the seeder ran (it logs "Reference data seeded"), and that Users is not empty.

7.4 Run the end-to-end flow once

Before signing the installation off, place one test order and carry it all the way through:

  1. Retail → New Order → note the order ID and account ID
  2. Technical → Installations → Record Check → Confirm → Start → Complete
  3. Technical → Connections → Activate
  4. Accounts → Run Billing
  5. Accounts → Bills → open the draft → Issue bill
  6. Retail → Bills & Payments → open the bill → Record a Payment
  7. Customer → sign in with the account ID → the paid bill is on the dashboard

If step 6 shows no payment form, check the bill's status (it must not be Draft) and its outstanding balance (it must be greater than zero). The invoice page states which of the two is blocking it.

Step 3 is the one people miss. A connection left Pending is never picked up by the billing run.

7.5 Change the seed passwords

Before handing the system to anyone else:

  1. Sign in as each staff user.
  2. Open Profile and change the password.
  3. For the administrator in particular, do this first.

7.6 Delete the test data

Remove the order and customer created in 7.4, or restore the database from a clean backup, so the system starts its real life empty.

8. Publishing for Deployment

8.1 Create a publish output

dotnet publish -c Release -o C:\publish\nexus

The output in C:\publish\nexus is self-contained as a set of files and is ready to be copied to a server. It requires the ASP.NET Core 8 Runtime to be installed on the target machine.

For a machine with no .NET runtime, publish self-contained:

dotnet publish -c Release -r win-x64 --self-contained true -o C:\publish\nexus

The output is larger but needs nothing pre-installed.

8.2 Prepare the target server

  1. Install the ASP.NET Core 8 Runtime (Hosting Bundle if using IIS) —

  1. Ensure SQL Server is reachable from the server.
  2. Create the database with dotnet ef database update, or restore a backup.

8.3 Production configuration

Do not deploy appsettings.json with the development connection string. Use appsettings.Production.json, which overrides the base file and must not be committed to source control:

{
  "ConnectionStrings": {
    "NexusDb": "Server=SQL01;Database=NexusDb;User Id=nexus_app;Password=<strong-password>;TrustServerCertificate=True;MultipleActiveResultSets=True;Connect Timeout=60"
  },
  "Serilog": {
    "MinimumLevel": {
      "Default": "Warning"
    }
  }
}

Also before going live:

  • Create a least-privilege SQL login. db_datareader and db_datawriter

only. Never sa.

  • Keep the login rate limits tight. The defaults are already tight.
  • Set security.sessionMinutes to a value appropriate to the environment.
  • Change every seed password (section 7.5).
  • Serve over HTTPS only. HSTS is sent automatically when the request is

already on TLS.

8.4 Deployment checklist

# Task
1 ASP.NET Core 8 Runtime installed on the server
2 Database created and migrated
3 appsettings.Production.json written with production credentials
4 Publish output copied to the server
5 Application pool identity granted access to the publish folder and to Logs/
6 Site bound in IIS with an HTTPS certificate
7 Seed passwords changed
8 One end-to-end order placed and completed as a smoke test
9 Test data removed
10 Backup schedule configured (section 10)

9. Deploying to IIS

9.1 Install the hosting bundle

Download and install the ASP.NET Core 8 Hosting Bundle (). This installs the runtime and the ASP.NET Core Module for IIS. Restart IIS afterwards:

iisreset

9.2 Create the site

  1. Open IIS Manager (inetmgr).
  2. Right-click Sites → Add Website.
  3. Set:
  4. Site name: Nexus
  5. Physical path: C:\inetpub\nexus (the publish output)
  6. Binding: https, port 443, with your certificate and host name
  7. Recommended: put the site in its own application pool with

.NET CLR Version: No Managed Code — the ASP.NET Core Module handles the runtime itself.

9.3 Grant folder permissions

The application pool identity needs:

Folder Permission
The publish folder Read & Execute
Logs\ Modify (Serilog writes here) 
icacls C:\inetpub\nexus /grant "IIS AppPool\Nexus:(OI)(CI)(RX)"
icacls C:\inetpub\nexus\Logs /grant "IIS AppPool\Nexus:(OI)(CI)(M)"

9.4 Verify

Browse to the site. If you see a 500 with no detail, that is usually a configuration or permission problem — check the log file under Logs\, which will name the actual cause.

9.5 Common IIS issues

Symptom Cause Fix
500.30 — app failed to start Bad connection string, or database unreachable Check Logs\; test the connection string from the server
500.31 — framework not found Runtime not installed Install the Hosting Bundle, then iisreset
502.5 — process failure Application pool identity lacks folder access Grant the permissions in 9.3
403 on static files wwwroot not readable icacls on the publish folder
Page loads but unstyled Static file middleware or path mismatch Confirm wwwroot was published

10. Backup and Restore

10.1 What to back up

Item Why
The NexusDb database All business data
appsettings.Production.json Production configuration
Uploaded files, if any Attachments
The publish folder Only if you cannot rebuild from source

10.2 Database backup

Via SSMS: right-click NexusDb → Tasks → Back Up…, choose a destination and run.

Via T-SQL:

BACKUP DATABASE NexusDb
TO DISK = 'C:\Backups\NexusDb_Full.bak'
WITH INIT, STATS = 10;

SQL Server Express does not support WITH COMPRESSION. Adding it fails with "BACKUP DATABASE WITH COMPRESSION is not supported on Express Edition." Leave it off on Express.

Schedule this as a SQL Server Agent job — or, on Express, as a Windows Task Scheduler job invoking sqlcmd with the statement above, since Express has no Agent.

10.3 Restore

RESTORE DATABASE NexusDb
FROM DISK = 'C:\Backups\NexusDb_Full.bak'
WITH REPLACE;

If you are restoring onto a server with different file paths:

RESTORE DATABASE NexusDb
FROM DISK = 'C:\Backups\NexusDb_Full.bak'
WITH MOVE 'NexusDb'     TO '<new data path>\NexusDb.mdf',
     MOVE 'NexusDb_log' TO '<new data path>\NexusDb_log.ldf',
     REPLACE;

10.4 Taking a backup before an upgrade

Always back up immediately before applying migrations:

BACKUP DATABASE NexusDb TO DISK = 'C:\Backups\NexusDb_pre-upgrade.bak' WITH INIT;

11. Upgrading the Application

When the source has moved on and the schema has changed:

1. Back up the database.

BACKUP DATABASE NexusDb TO DISK = 'C:\Backups\NexusDb_pre-upgrade.bak' WITH INIT;

2. Stop the running application. A running process locks its own executable, so the build will fail otherwise.

3. Apply new migrations.

cd /d C:\Projects\Naxus-internet-service-mangment
dotnet ef database update

Review the migration files first. A migration that drops or renames a column is worth reading before it runs.

4. Rebuild and republish.

dotnet publish -c Release -o C:\publish\nexus

5. Start the application and walk the first-run checklist (section 7), at least as far as the end-to-end order.

11.1 Rolling back a migration

dotnet ef database update <PreviousMigrationName>

Get the names with:

dotnet ef migrations list

A down-migration is not always lossless. A migration that dropped a column cannot restore the data it held. This is why step 1 is not optional.

12. Troubleshooting

Build and run

dotnet : command not found The .NET SDK is not installed, or not on PATH. Reinstall, then open a fresh terminal.

MSB3021 / MSB3027 — file locked The application is running. Stop it, then build.

CS prefixed errors Genuine compile errors, reported with file and line. Read the first one — later errors are frequently knock-on effects of the first.

Port already in use Another process holds 5096. Change the port in Properties/launchSettings.json, or find and stop the other process:

netstat -ano | findstr :5096
taskkill /PID <pid> /F

Database

A network-related or instance-specific error occurred SQL Server is unreachable. Confirm the instance name and that the service is running:

sqlcmd -S .\SQLEXPRESS -E -Q "SELECT @@VERSION"

Login failed for user Wrong credentials, or the login lacks a database user. Check the connection string, then confirm the login exists and is mapped (section 4.3).

Cannot open database "NexusDb" requested by the login The database does not exist, or the login is not mapped to it. Run dotnet ef database update.

There is already an object named 'X' in the database Migrations are out of step with the schema — often because a .bak was restored and migrations were then applied. Check __EFMigrationsHistory and reconcile:

SELECT MigrationId FROM __EFMigrationsHistory ORDER BY MigrationId;

Seeding does not appear to run Seeding failures are logged and swallowed so the application still starts. Search the log for "Seeding failed" — the exception names the cause. A missing unique index or a mismatched column type is the usual reason.

Application

Sign-in succeeds but immediately returns to the login page Usually a stale or misconfigured cookie. Clear cookies for the site, and confirm Cookie.SecurePolicy = SameAsRequest matches whether you are on HTTP or HTTPS.

Too many attempts. Please wait a minute and try again. The sign-in rate limiter has been triggered. Wait for the window to pass, or raise Security:LoginRateLimit:PermitLimit for a test environment.

403 Access Denied on a page that should work The signed-in role does not own that screen. Check the [Authorize] attribute on the controller and confirm you are using the intended account.

Inline scripts blocked, page partially broken The CSP is rejecting them. Confirm ScriptNonceTagHelper is registered — the project's Views/_ViewImports.cshtml needs @addTagHelper *, NEXUS.Services — and that the tag does not carry src (a nonce on an external script tag is ignored by the browser).

InvalidOperationException: The configured execution strategy 'SqlServerRetryingExecutionStrategy' does not support user-initiated transactions A manual transaction was opened outside the execution strategy. Wrap it (see the developer guide, section 9.5).

A page returns 500 with no visible detail In production, exception detail is hidden from the browser and the branded error page is shown instead. The real cause is in Logs/nexus-<date>.log.

Data

A customer cannot see their bill The bill is still a Draft. Issue it from Bills.

A new connection is not billed The connection is still Pending. Change it to Active.

An invoice shows a zero total Either the advance covered it, or the period produced no charges. Both are legitimate, and the invoice states which.
