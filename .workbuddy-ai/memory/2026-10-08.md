## Phase F6 — Settings save ko actually chalana

Do alag bugs the, dono build+curl se proven aur fixed.

### Bug 1 — CS0111 (duplicate member)

GET aur POST dono `Settings(CancellationToken ct)` the. **C# attributes ko method
signature ka hissa nahi maanta**, is liye `[HttpGet]` / `[HttpPost]` hone ke
bawajood compiler unhe duplicate samajhta hai aur `CS0111`. (Yaad rakho: MVC
action-name ki uniqueness *attributes* se nahi, method naam se hoti hai.)

Fix: POST ka naam `SaveSettings` + `[ActionName("Settings")]` — route aur form
ka `asp-action="Settings"` bilkul wahi rehta hai.

### Bug 2 — POST 400 (antiforgery)

`Settings(IFormCollection form, CancellationToken ct)` likhne se model binder
request body pehle parse kar leta tha, aur `[ValidateAntiForgeryToken]` us ke
baad 400 de deta. Prove: usi session mein `ToggleServed` POST 302 de raha tha —
yani token theek tha, masla sirf is action ke parameter ka tha.

Fix: parameter hata kar seedha `Request.Form` padho.

### Bool save ka third bug

`form.ContainsKey(key) ? "true" : "false"` — yani scripted client
`feature.maintenance=false` bhejta to bhi **true** save hota. Ab value bhi
check hoti hai. Browser ka unchecked checkbox key bhejta hi nahi, is liye
absence = off (normal case), aur present `"false"` bhi off.
