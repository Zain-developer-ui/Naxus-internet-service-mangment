## 🎯 MIL GAYA — implicit required (systemic bug) — FIXED

Artifact bundle (`.testsprite/runs/792410e0-.../failure.json` + `steps/13-snapshot.html`)
ne asli wajah de di:

```
"The New Vendor form remained visible after clicking 'Add Vendor' and shows

```

DOM snapshot se confirm:
```html
<input ... data-val-required="The Tax / NTN Number field is required." id="TaxNumber" value="" class="input-validation-error">
<input ... data-val-required="The Address field is required." id="Address" value="" class="input-validation-error">
```
Aur view mein: `<label asp-for="TaxNumber">Tax / NTN Number <span class="opt">optional</span></label>`

**View kehta hai "optional", validation kehti hai "required".**

**Wajah:** **nullable reference types ka implicit required.** `TaxNumber`, `Address`,
`ContactPerson`, `Phone` — sab non-nullable `string` (initializer `= string.Empty`)
hain. `[Required]` attribute **nahi** hai, magar .NET 6+ ka MVC non-nullable
reference types ko khud required maan leta hai (`SuppressImplicitRequiredAttributeForNonNullableReferenceTypes`
ka default `false` hai).

**Yehi TC-025 (PO) aur TC-028 (order) ki bhi wajah thi** — order form mein
`PreferredTime` non-nullable `string` hai magar UI mein optional.

**Fix (ek line):**
```csharp
builder.Services.AddControllersWithViews(options =>
{
    options.SuppressImplicitRequiredAttributeForNonNullableReferenceTypes = true;
});
```

Ab sirf explicit `[Required]` lagta hai — aur views ke `*`/`optional` labels
(jo explicit attributes se match karte hain) **sach** ho gaye.

**Verify (live):**
```
vendor name : E2E Blank Optional 1791877435
final url   : /Admin/Vendors     ← list par redirect
saved       : True
field errors: []
```
Saare optional fields khaali chhod kar vendor ban gaya. Pehle `data-val-required`
bhi check kiya → ab **False**.

**🔑 SABSE BARA SABAK:** view mein `<span class="opt">optional</span>` likhna
kaafi nahi. Non-nullable `string` property **khud required** ban jati hai. Ya to
property `string?` karo, ya ye global option lagao.

`wwwroot/js/validation.js` **line 15**:

**Do formats, dono ek doosre ke khilaf:**

- Bina dash likho → client khush, **server reject** kar deta hai

**Natija: browser se order wizard kabhi submit hi nahi ho sakta.** Mere saare HTTP

### Isi file mein teen aur mismatch mile

| # | Kya | Client | Server |
|---|---|---|---|
| 1 | **Phone** | `^03\d{9}$` (no dash) | `^0\d{3}-\d{7}$` (dash) |
| 2 | **ContactPerson** | `contact` match hone se **phone rule** lagta hai | koi rule nahi (naam hai, phone nahi) |
| 3 | **Password** | min **6** chars | `MinimumLength = 8` |
| 4 | `inputmode="numeric"` | dash-required field par | mobile par dash key hi nahi hoti |

CNIC theek hai — client `^\d{5}-\d{7}-\d$` = server `^\d{5}-\d{7}-\d$`. ✓
Landline par client rule nahi lagta (naam mein "phone"/"mobile"/"contact" nahi). ✓
