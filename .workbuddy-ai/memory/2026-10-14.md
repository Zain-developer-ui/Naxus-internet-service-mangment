## 2. Advance carry-forward — negative bill khatam

**Masla:** `ApplyAdvanceAsync` poora advance ek hi line mein lagata tha. Advance
(500) charges (390) se zyada → bill **-123.46**.

**Faisla:** advance sirf utna absorb kare jitna period ka kharcha hai; baqi order
par bacha rahe aur agli bill par lage. (Negative invoice customer ke liye refund
jaisi lagti hai, aur baqi paisa phans jata hai.)

**Changes:**
- `ConnectionOrder.AdvanceApplied` (decimal) + `AdvanceRemaining` computed
- `BillingService.ApplyAdvanceAsync` → `AdvanceApplication(Order, Applied)` record
  return karta hai; `applied = min(remaining, max(0, charges))`
- `MarkAdvanceAdjusted(order, applied)` — `AdvanceApplied += applied`, aur
  `AdvanceAdjustedOn` sirf tab jab poora khatam ho
- Migration `20261014101417_AdvanceApplied`
- Migration `20261014101913_AdvanceAppliedBackfill` — **zaroori**: purane rows jinka
  `AdvanceAdjustedOn` set tha, unka `AdvanceApplied = QuotedAmount` kar diya, warna
  nayi logic wahi advance **dobara** credit kar deti
